# 사용설명서 (운영)

기능·대화 예시·사이트 설정은 README.md 에 있다. 여기는 **봇을 돌리고 고치는 법**만 적는다.

## 봇이 도는 방식
- `.github/workflows/main.yml` 이 `*/5` cron 으로 봇을 띄운다. 한 번 뜨면 `MAX_RUN_SEC`(5시간 30분)
  동안 켜져 있으며 10분마다 검색하고 버튼에는 바로 답한다. GitHub 가 한 실행을 6시간까지만 돌려준다.
- **2026-10-20 부터 cron 을 멈춰 두었다** (`schedule` 두 줄을 주석 처리). Run workflow 로 띄운 실행 하나만
  5시간 30분 돌고 끝난다. 다시 계속 돌리려면 주석을 풀고 머지한다. 아래 '대기 실행' 설명은 cron 이 켜졌을 때 이야기다.
- `concurrency: accommodation-bot`, `cancel-in-progress: false` — 봇은 항상 하나만 돈다.
  다음 실행은 대기(pending)하다가 앞 실행이 끝나면 이어받는다.
- 대기 중인 실행은 **시작할 때** `origin/main` 최신 코드를 받는다 ('최신 상태로 맞추기' 단계).
- cron 은 실제로 2~5시간 간격으로 들쭉날쭉 온다. 대기 실행이 없으면 공백이 생길 수 있다.

## 켜기 / 끄기
- **끄기**: `gh api -X PUT repos/totida/recan/actions/workflows/main.yml/disable` 후 실행 중인 run 취소
  (`gh api -X POST repos/totida/recan/actions/runs/<id>/cancel`). 웹에서는 Actions → 숙소 예약 알림봇 →
  ⋯ → Disable workflow.
- **켜기**: `.../main.yml/enable` 후 `run_workflow`(workflow_dispatch, ref=main) 로 바로 띄운다.
  웹에서는 Enable workflow → Run workflow.
- 꺼진 동안 텔레그램은 메시지를 약 24시간만 보관한다. 그보다 오래된 입력은 처리되지 않는다.
- 상태 확인: `gh api repos/totida/recan/actions/workflows/main.yml --jq .state`

## 새 코드로 교체 (머지 후 반드시)
실행 중인 봇은 시작할 때 받은 코드를 계속 쓴다. 머지만 해서는 반영되지 않는다.
1. 대기(pending) 실행이 **있으면** → 실행 중인 run 만 취소. 대기 실행이 새 main 으로 뜬다.
2. 대기 실행이 **없으면** → 먼저 `run_workflow` 로 새 실행을 띄운 뒤 실행 중인 run 취소.
   (먼저 취소하면 다음 cron 까지 봇이 비어 있다.)
3. 새 job 의 '최신 상태로 맞추기' 시각이 머지보다 뒤인지, '자체 테스트'가 통과했는지 확인.
- 교체하는 1~2분 사이에는 봇이 응답하지 않는다. 그때 "느리다"는 보고는 교체 탓일 수 있다.

## 점검 도구 (Actions, workflow_dispatch)
작업 브랜치를 ref 로 주면 그 브랜치 코드로 돈다. 로그는 job 이 끝나야 받아진다.
- `check-sites.yml` — 입력: query, checkin, checkout, guests, dump. 사이트별 카드 수·이름 일치·판정,
  네이버/야놀자는 상세 페이지 판정까지 찍는다. **오탐 확인은 이것으로.**
- `check-url.yml` — 주소 하나를 열어 본문·가격·마감 표시·링크를 보여준다 (chars 로 길이 조절).
- check-sites 는 '네이버 예약'에서 찾은 숙소 번호로 네이버 호텔 가격비교 판정까지 찍는다.
- 봇 실행(main.yml) 로그는 job 이 끝나야(5시간 30분 또는 취소) 받아진다. 2026-10-20 부터
  `PYTHONUNBUFFERED` 라 취소해도 남고, 줄마다 시각이 찍힌다. `🔎 검색:`·`⏱️ N초`·`📨 새 입력`
  시각으로 어디서 느렸는지 본다. 그 전 실행은 취소하면 검색 결과가 통째로 사라졌다.
  사용자가 받은 판정을 바로 확인하려면 같은 숙소·날짜로 check-sites 를 돌린다.

## 비밀값 (Settings → Secrets and variables → Actions)
| 이름 | 용도 |
|---|---|
| TELEGRAM_TOKEN | 봇 토큰 |
| GIST_ID / GIST_TOKEN | 등록 내용 저장용 비밀 Gist. 토큰은 `gist` 권한만 |
| OWNER_CHAT_ID | 주인 고정. 있으면 주인이 바뀌지 않는다 (`내아이디` 명령으로 🔒 표시 확인) |

## 문제가 생겼을 때
- **Actions 가 전부 `startup_failure`**, `git push`·PR 생성이 403 → GitHub 계정 이메일 미인증일 수 있다
  ("At least one email address must be verified"). 2026-09-23 실제로 겪음. github.com/settings/emails.
  그 사이 봇이 6시간 한도로 끝나면 다음 실행이 안 떠서 봇이 멈춘다.
- **오탐 알림** → 사용자가 보낸 화면 글자로 테스트를 만들고 `check-sites.yml` 로 실제 판정 확인.
- **머지했는데 그대로** → 위 "새 코드로 교체" 절차를 안 한 것.
