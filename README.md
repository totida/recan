# 숙소 빈방 알림 텔레그램 봇

원하는 숙소 이름을 텔레그램으로 보내면,

1. 봇이 **네이버에서 그 숙소를 찾아 주소와 함께 후보를 보여주고 버튼으로 고르게** 하고,
2. **오늘 날짜 기준 달력**에서 체크인·체크아웃 날짜를, 이어서 **인원**을 누르게 한 뒤,
3. **여기어때 · 야놀자 · 네이버 예약 · 하나투어**를 **1시간마다** 검색해
   예약 가능한 방이 보이면 알려줍니다.

검색 결과는 고르신 주소와 다시 대조해, 이름만 같은 다른 지역 숙소를 걸러냅니다.

## 대화 예시

```
나 : 비토애 산청
봇 : 📍 '비토애 산청'을(를) 네이버에서 찾아봤어요. 어느 숙소인가요?
     [1. 비토애 산청 · 경남 산청군 시천면 지리산대로 123]
     [2. 비토애 산청 별관 · 경남 산청군 단성면 2-3]
     [🔎 목록에 없어요 (주소 직접 입력)]
     [⏭️ 주소 없이 진행]  [✖️ 취소]
나 : (1번 버튼 탭)
봇 : 🏨 비토애 산청
     📆 체크인(입실) 날짜를 선택해 주세요.
     [◀] [2026년 9월] [▶]
     [월][화][수][목][금][토][일]
     [·][·][[9]][10][11][12][13]     ← 오늘은 [9]처럼 표시, 지난 날짜(·)는 못 누름
     ...
     [✍️ 직접 입력] [✖️ 취소]
나 : (10월 3일 탭 → 체크아웃 달력 → 10월 5일 탭)
봇 : ✅ 등록 완료!
     🏨 비토애 산청
     📍 경남 산청군 시천면 지리산대로 123
     📅 2026-10-03 → 2026-10-05 (2박 · 2명)

(1시간마다 검색 → 방이 나오면)
봇 : 🚨 예약 가능한 방을 찾았어요!
     ✅ 여기어때 · 예약 가능
         • 비토애 산청 펜션 120,000원
           📍 경남 산청군 시천면 (주소 일치)
           https://...
     ⛔ 야놀자 · 마감
     🔍 하나투어 · 검색 결과 없음
```

버튼 대신 글자로 보내도 다 됩니다.
숙소 후보는 번호(`1`), 날짜는 `5/2~5/3` · `내일 2박` · `이번주말`, 인원은 `4명`.
한 줄로 `비토애 산청 5/2~5/3 4명` 도 되고, 네이버 숙소 링크를 붙여넣어도 됩니다.

### 명령어

| 입력 | 동작 |
| --- | --- |
| `도움말` / `/start` | 사용법 안내 |
| `목록` | 등록된 알림 보기 |
| `삭제 2` | 2번 알림 삭제 |
| `삭제 전체` | 모두 삭제 |
| `지금` | 주기를 기다리지 않고 즉시 검색 (결과가 없어도 보고) |
| `인원 2 4` | 2번 알림을 4명으로 변경 (바로 다시 검색) |
| `취소` | 입력 중이던 등록 취소 |
| 등록 도중 다른 숙소 이름 | 하던 등록을 접고 그 숙소로 새로 시작 |
| `예` / `아니오` | 확인 단계 승인 / 다시 입력 |
| `없음` | 네이버 후보에 없을 때 → 주소 직접 입력 |
| `건너뛰기` | 주소 없이 진행 (이름만으로 대조) |
| 트리플 숙소 링크 붙여넣기 | 그 숙소를 인터파크 트리플에서도 함께 확인 |

### 날짜 입력 형식

`2026-05-02~2026-05-03`, `2026.5.2~2026.5.4`, `20260502-20260503`,
`5/2~5/3`, `5월 2일부터 5월 3일까지`, `5/2 2박`, `내일 1박`, `이번주말`, `다음주말`

날짜 하나만 보내면 1박으로 계산하고, 연도를 빼면 오늘 이후 가장 가까운 연도로 해석합니다.
인원은 등록 마지막에 버튼으로 고릅니다. 한 줄 입력에 `4명`을 적으면 그 단계를 건너뜁니다.
인원은 검색 주소에 그대로 들어가므로, **그 인원이 묵을 수 있는 객실만** 걸러집니다.
등록한 뒤에는 `인원 2 4` 로 바꿀 수 있습니다.

### 주소 확인이 왜 필요한가요

'비토애 산청'처럼 이름만으로는 지역이 다른 동명 숙소가 검색될 수 있습니다.
그래서 등록 전에 **네이버에서 후보를 찾아 주소와 함께 고르게 하고**(못 찾으면 직접 입력),
예약사이트 검색 결과 카드에서도 같은 지역명이 보이는지 한 번 더 대조합니다.

- 주소가 일치하는 결과가 하나라도 있으면 → 그 결과들만 알려줍니다 (`주소 일치`)
- 카드에 주소가 아예 표시되지 않으면 → 알려주되 `⚠️ 주소 미확인`으로 표시합니다
- 주소를 `건너뛰기` 했다면 → 이름만으로 대조합니다

## 동작 방식

- GitHub Actions가 `bot.py`를 실행합니다. (예약 실행은 5분마다 요청하지만,
  GitHub가 크게 지연시켜 **실제로는 2~5시간 간격**으로 돕니다 — 이 저장소의 실행 기록 기준.
  검색 주기로는 충분하지만 버튼 응답을 기다리기엔 길어서, **등록할 때는
  Actions → Run workflow 로 한 번 깨워주는 것**을 권합니다.)
  - 새 메시지·버튼 입력이 없으면 **즉시 종료**해서 Actions 사용 시간을 아낍니다.
  - 대화가 오가는 중이면 **마지막 입력 후 150초(IDLE_EXIT_SEC)까지, 최대 15분
    (MAX_RUN_SEC) 동안 머물며 long polling** 해서 버튼을 누르면 1초 안에 반응합니다.
    → 한 번 깨우면 숙소 등록 한 건을 끊김 없이 끝낼 수 있습니다.
    (깨어 있지 않을 때 누른 버튼도 텔레그램에 쌓여 있다가 다음 실행에서 처리되므로
     사라지지는 않습니다. 다만 그만큼 기다려야 합니다.)
  - 항목별로 마지막 검색 후 **60분**이 지났을 때만 실제 사이트 검색 (등록 직후 1회는 즉시)
- 검색은 헤드리스 크롬(Selenium)으로 각 사이트의 검색 페이지를 열어
  결과 카드에서 숙소 이름이 일치하는 항목을 찾고, 가격이 보이면 "예약 가능",
  `예약마감/만실/품절` 등이 보이면 "마감"으로 판단합니다.
- 네이버 상세 링크가 등록된 항목은 기존 방식(객실 수 vs `예약마감` 수 비교)으로 확인하며,
  이때도 페이지 내용에서 승인받은 주소를 다시 대조합니다.
- 알림은 **결과가 바뀌었거나 마지막 알림 후 60분이 지났을 때**만 보내 스팸을 막습니다.
  빈방이 다시 모두 마감되면 한 번 알려주고 계속 감시합니다.
- 체크아웃 날짜가 지난 항목은 자동으로 종료·삭제됩니다.

## 파일 구조

| 파일 | 역할 |
| --- | --- |
| `bot.py` | 대화 처리, 주기 검색, 알림 전송 (진입점) |
| `keyboards.py` | 달력 · 숙소 후보 선택 인라인 키보드 |
| `dateparse.py` | 한국어 날짜/인원 파싱 |
| `search.py` 의 `address_*` | 검색 결과 주소 재검증 |
| `search.py` | 사이트 검색·화면 해석 엔진 (Selenium) |
| `providers.json` | **검색할 사이트 설정 (URL·선택자)** |
| `storage.py` | 등록 내용 저장(Gist 또는 파일) 및 구버전 자동 마이그레이션 |
| `telegram_api.py` | 텔레그램 API 래퍼 |
| `tests/` | 브라우저 없이 도는 단위 테스트 |

## 설정

GitHub 저장소 → Settings → Secrets → Actions 에 `TELEGRAM_TOKEN` 을 등록하세요.

워크플로 환경변수로 조절할 수 있는 값:

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `SEARCH_INTERVAL_MIN` | 60 | 검색 주기(분) |
| `NOTIFY_INTERVAL_MIN` | 120 | 빈방이 계속 열려 있을 때 다시 알리는 간격(분). 처음 열린 순간은 이 값과 상관없이 바로 알립니다 |
| `STATE_TTL_MIN` | 30 | 등록을 하다 만 채로 이만큼 지나면, 다음 메시지는 새 요청으로 봅니다(분) |
| `MAX_WATCHES` | 10 | 채팅방당 최대 알림 수 |
| `POLL_TIMEOUT_SEC` | 20 | long polling 대기(초) |
| `IDLE_EXIT_SEC` | 60 | 이만큼 조용하면 실행 종료(초). **0 이면 상시 대기** |
| `MAX_RUN_SEC` | 300 | 한 번의 실행 상한(초) |
| `GIT_PERSIST` | (없음) | `1` 이면 등록 내용이 바뀔 때마다 저장소에 커밋 |
| `GIST_ID` · `GIST_TOKEN` | (없음) | 둘 다 있으면 등록 내용을 **비공개 Gist** 에 저장 |

### 등록 내용을 어디에 저장할까

기본은 저장소의 `users.json` 입니다. 저장소가 **공개**라면 쓰는 사람의 채팅 ID와
감시 목록(숙소·날짜)도 함께 공개됩니다. 나 혼자 쓰면 상관없지만, 다른 사람에게
열어줄 생각이라면 남의 정보까지 공개되므로 저장 위치를 옮기는 편이 낫습니다.

`GIST_ID` 와 `GIST_TOKEN` 을 시크릿으로 넣으면 비공개 Gist 에 저장합니다.

1. GitHub 토큰 발급 — `gist` 권한만 있으면 됩니다 → 저장소 시크릿 `GIST_TOKEN`
2. secret gist 생성 (파일명 `users.json`, 내용 `{}`) → 주소 끝의 id 를 `GIST_ID`
3. 워크플로에 두 값을 env 로 넘기면 끝입니다.

`users.json` 은 저장소에 없습니다. Gist 또는 봇이 도는 서버의 파일에만 존재합니다.
내용을 보려면 GitHub 에 로그인해 <https://gist.github.com> 에서 열면 되고,
저장할 때마다 Revisions 에 이력이 쌓여 예전 상태로 되돌릴 수도 있습니다.

Gist 를 쓰는 동안에는 저장소에 아무것도 커밋하지 않습니다.
Gist 를 읽지 못하면 **빈 상태로 시작하지 않고 멈춥니다** — 그래야 다음 저장 때
등록 내용이 전부 지워지는 사고를 막습니다.

집 PC·오라클 클라우드 같은 상시 서버에서 돌린다면 두 값을 비워두세요.
그러면 그 서버의 파일에만 저장되어 애초에 공개될 일이 없습니다.

### 두 가지 실행 방식

| | 짧게 깨우기 (`IDLE_EXIT_SEC=60`) | 상시 대기 (`IDLE_EXIT_SEC=0`) |
| --- | --- | --- |
| 동작 | 입력이 없으면 즉시 종료 | `MAX_RUN_SEC` 까지 계속 켜둠 |
| 탐지 주기 | 실제 2~3시간 (GitHub 가 예약 실행을 미룸) | 설정한 검색 주기 그대로 (10분 등) |
| 버튼 반응 | 다음 실행까지 대기 | 1초 이내 |
| Actions 사용 시간 | 월 400~500분 | 사실상 24시간 → **공개 저장소에서만 현실적** |

상시 대기는 실행 하나가 5시간 30분 동안 이어지고, 끝나면 대기 중이던 다음
실행이 이어받습니다. 동시에 둘이 돌지 않도록 `concurrency` 로 묶여 있습니다.

> 버튼 반응을 항상 즉시로 만들려면 `IDLE_EXIT_SEC`/`MAX_RUN_SEC`를 키우면 되지만,
> 그만큼 Actions 사용 시간이 늘어납니다(비공개 저장소는 분 단위 과금).
> 저장소를 공개로 바꾸면 Actions 사용 시간이 무료라 계속 켜둘 수 있습니다.

## 사이트 설정 손보기

예약 사이트는 URL 구조와 화면 구조를 자주 바꿉니다.
그럴 때는 코드가 아니라 **`providers.json` 만** 고치면 됩니다.

```json
{
  "key": "goodchoice",
  "name": "여기어때",
  "enabled": true,
  "url": "https://www.goodchoice.kr/product/search/2?keyword={query}&sel_date={checkin}&sel_date2={checkout}&persons={guests}",
  "card_selectors": ["a[href*='/product/']", "li[class*='item']"],
  "wait": 6,
  "scrolls": 2
}
```

- `url` 안에서 쓸 수 있는 값: `{query}` `{checkin}` `{checkout}`
  `{checkin_compact}`(YYYYMMDD) `{checkout_compact}` `{checkin_dot}`(YYYY.MM.DD)
  `{checkout_dot}` `{guests}` `{nights}`
`place_lookup` 항목은 숙소 이름 → 주소 후보를 찾는 네이버 검색 설정입니다.
`urls` 를 위에서부터 시도하다가 후보를 찾으면 멈춥니다.

- `card_selectors` 는 위에서부터 시도하며, 모두 실패하면 페이지의 모든 링크에서
  숙소 이름을 찾는 방식으로 대체합니다. 즉 선택자가 틀려도 완전히 죽지는 않습니다.
- 특정 사이트를 끄려면 `"enabled": false`.
- 사이트를 추가하려면 같은 형식으로 항목을 하나 더 넣으면 됩니다.

### 사이트별 확인 결과 (2026-09-12 실측)

| 사이트 | 상태 | 비고 |
| --- | --- | --- |
| 야놀자 | ✅ 정상 | 이름·가격·주소·날짜 모두 확인. `nol.yanolja.com` 검색 사용 |
| 네이버 예약 | ✅ 정상 | 검색 결과의 장소 링크를 따라가 객실 수 vs 예약마감 수 비교 |
| 여기어때 | ✅ 정상 | `yeogi.com` 검색 사용. 취급하지 않는 숙소는 `🚫 미취급` 으로 표시 |
| 부킹닷컴 | ✅ 정상 | 영문 표기(`Lahan Select Gyeongju`)를 한글 이름과 로마자로 대조 |
| 아고다 | ⏸️ 꺼둠 | 카드는 읽히나 검색 결과에 해당 숙소가 나오지 않음 |
| 트립닷컴 | ⏸️ 꺼둠 | 검색 결과가 끝내 그려지지 않음(필터 UI만 읽힘) |
| 하나투어 | ⏸️ 꺼둠 | 검색 결과가 렌더링되지 않아 메뉴 항목만 읽힘 (대형 호텔로도 동일) |
| 인터파크 트리플 | 🔗 링크 등록 | 이름으로는 찾아갈 수 없음. 숙소 링크를 보내면 그 링크로 감시 (아래 참고) |

`🚫 미취급` 은 고장이 아닙니다. 사이트가 직접 "검색 결과가 없어요"라고 답한
경우이며, 그 사이트가 해당 숙소를 팔지 않는다는 뜻입니다.
국내 펜션·글램핑은 야놀자·네이버에, 호텔·리조트는 아고다·부킹닷컴·트립닷컴에 주로 있습니다.
숙소 한 곳을 여러 사이트에서 찾으므로, 어떤 사이트가 `🚫 미취급` 이어도 다른 곳에서 잡히면 됩니다.

### 인터파크 트리플은 왜 링크가 필요한가요

트리플은 **숙소 이름으로 찾아갈 방법이 없습니다.** 실측한 내용입니다.

| 시도한 곳 | 결과 |
| --- | --- |
| `triple.guide/search?q=` / `?keyword=` | 본문 142자짜리 빈 화면만 그려짐 |
| 검색 화면의 '국내도시' 탭 | 12곳(가평·양평, 강릉·속초, 경주, 부산, 여수, 인천, 전주, 제주, 춘천·홍천, 태안, 통영·거제·남해, 포항·안동)이 나오지만 `href` 없는 `div` 라, 누르면 앱 설치 안내창만 뜸 (창을 닫고 다시 눌러도 같음) |
| `triple.guide/regions` 색인 | "알 수 없는 오류" 화면 |
| 덕덕고 `site:triple.guide 쏠비치 남해` | 링크는 나오지만 전부 `/articles/`·`/attractions/`, 숙소 페이지 없음 |
| 빙 | 검색 결과 대신 마이크로소프트 홍보 페이지 |
| 구글 | "비정상 트래픽" 차단 페이지 |
| 네이버 | 트리플 값이 글로는 보이지만 링크는 네이버 내부 주소로 감싸져 있음 |
| `travel.interpark.com/search` | 404 |

반면 **숙소 상세 페이지는 아주 잘 읽힙니다.** 이름·주소·객실별 가격과 잔여 수량까지
그대로 나오고, 주소 뒤에 `skipInitialCache=true` 를 붙이면 우리가 넣은 날짜·인원이
그대로 반영됩니다. (이 값이 없으면 트리플이 캐시해 둔 기본 날짜 화면을 줍니다.)

지역별 목록(`/regions/{지역번호}/hotels`)도 마찬가지로 잘 읽힙니다. 이름·지역·가격이
모두 나오고 날짜·인원도 주소로 지정됩니다. 문제는 **지역번호를 알아낼 방법이 없다**는
점입니다. 위 표처럼 도시 목록이 링크가 아니라서 번호를 주워 올 수가 없습니다.

한 가지 더 알아둘 점이 있습니다. 트리플의 국내 펜션 재고는 야놀자에서 받아옵니다.
숙소 상세 페이지 첫 줄에 `출처 www.yanolja.com/` 이라고 적혀 있습니다.
**이미 야놀자를 보고 있다면 트리플이 새로 알려주는 것은 거의 없습니다.**

그래서 트리플은 **원하는 사람만 링크를 한 번 등록**하는 방식입니다. 안 써도 됩니다.

1. 트리플 앱·웹에서 그 숙소 페이지를 열어 링크를 복사합니다.
2. 봇에게 그 링크를 보냅니다. (알림이 여러 개면 어디에 붙일지 버튼으로 고릅니다.)
3. 이후로는 날짜·인원을 바꿔도 봇이 알아서 그 링크를 다시 열어 확인합니다.

`목록` 에 `🔗 인터파크 트리플 연결됨` 이라고 표시됩니다.

**사이트가 구조를 바꾸면** 점검 워크플로가 카드 0개일 때 실제로 열린 주소·화면
제목·본문을 찍어줍니다. 그걸 보고 `providers.json` 의 `urls` 에 올바른 주소를
추가하면 됩니다.

## 테스트하는 방법

### 0단계 — 준비 (최초 1회)

1. 텔레그램에서 **@BotFather** → `/newbot` → 토큰 발급
2. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
   → 이름 `TELEGRAM_TOKEN`, 값에 발급받은 토큰
3. 만든 봇과의 대화창에서 `/start` 한 번 보내기

### 1단계 — 로직 테스트 (인터넷·크롬·토큰 불필요, 몇 초)

```bash
python -m unittest discover -s tests -q
```

날짜 파싱, 달력 경계, 후보 선택, 주소 대조, 알림 주기까지 99개 테스트가 돕니다.
GitHub Actions 에서도 봇 실행 전에 자동으로 돌기 때문에, 실패하면 봇이 뜨지 않습니다.

### 2단계 — 대화 시뮬레이터 (텔레그램 없이 흐름 확인)

```bash
pip install -r requirements.txt
python tools/chat_sim.py
```

터미널에서 봇과 실제로 대화해 볼 수 있습니다.

```
👤 비토애 산청
🤖 📍 '비토애 산청'을(를) 네이버에서 찾아봤어요...
   [b1] 1. 비토애 산청 · 경남 산청군 시천면...
👤 b1            ← 버튼은 b번호로 누릅니다
👤 b10           ← 달력에서 날짜 선택
👤 !search       ← 지금 검색해서 알림 내용 보기
👤 !db           ← 저장된 상태 보기
```

기본은 가짜 데이터라 인터넷이 없어도 됩니다.
`--live` 를 붙이면 실제 크롬으로 네이버 주소 검색과 사이트 검색까지 수행합니다.

### 3단계 — 예약사이트가 실제로 검색되는지 점검 ⭐

가장 확인이 필요한 부분입니다. **로컬에 아무것도 설치하지 않고** GitHub에서 돌릴 수 있습니다.

> GitHub 저장소 → **Actions** 탭 → 왼쪽 **예약사이트 검색 점검** →
> **Run workflow** → 숙소 이름 / 체크인 / 체크아웃 입력 → 실행 → 로그 확인

로그에 사이트마다 이렇게 찍힙니다.

```
🏨 여기어때
  → https://www.goodchoice.kr/product/search/2?keyword=...
  카드 24개 · 이름 일치 2개 → 예약 가능
      ✅ 비토애 산청 120,000원 (주소 일치)
```

마지막에 요약이 나옵니다.

| 로그 | 뜻 | 할 일 |
| --- | --- | --- |
| `카드 0개` | 화면을 못 읽음 | `providers.json` 의 `card_selectors` 수정 |
| `이름 일치 0개` | 검색 자체가 안 됨 | `providers.json` 의 `url` 형식 수정 |
| `예약 가능 / 마감` | 정상 | 그대로 두기 |

로컬에 크롬이 있다면 같은 점검을 이렇게도 할 수 있습니다.

```bash
python tools/check_sites.py --query "비토애 산청" \
       --checkin 2026-10-03 --checkout 2026-10-05 --dump
```

### 4단계 — 실제 텔레그램으로 테스트

1. **Actions 탭 → 숙소 예약 알림봇 → Run workflow** (브랜치를 골라 실행할 수 있습니다)
   - 자동 실행(5분 주기)은 기본 브랜치(`main`)에서만 동작하므로,
     상시로 쓰려면 이 브랜치를 `main` 에 머지해야 합니다.
2. 텔레그램에서 봇에게 `비토애 산청` 을 보냅니다.
3. **먼저 메시지를 보낸 뒤 Run workflow 를 누르면**, 그 실행 동안(약 1분)
   버튼이 즉시 반응하므로 등록을 한 번에 끝낼 수 있습니다.
4. 등록되면 곧바로 1차 검색이 돌고 결과 메시지가 옵니다.
5. `지금` 이라고 보내면 주기를 기다리지 않고 다시 검색합니다.

### 확인 포인트

- Actions 로그의 `📨 새 입력 N건` — 텔레그램 메시지를 받고 있는가
- 로그의 `🔎 검색: … / - 여기어때: available (1건)` — 사이트별 판정
- 커밋 목록에 `Update user database` — 등록 내용이 `users.json` 에 저장됨
- 답장이 전혀 없다면: `TELEGRAM_TOKEN` 시크릿, 봇과 `/start` 했는지 확인

### 문제가 생겼을 때

| 증상 | 원인 / 조치 |
| --- | --- |
| 답장이 없음 | `TELEGRAM_TOKEN` 미설정 또는 오타 (로그에 `TELEGRAM_TOKEN 환경변수가 없습니다`) |
| 버튼을 눌러도 한참 뒤 반응 | 봇이 깨어 있지 않아서입니다. Actions → Run workflow 로 깨우고 등록하세요 |
| 봇이 두 번 답하거나 메시지를 놓침 | 같은 토큰을 쓰는 봇이 두 곳에서 도는 경우 — 워크플로는 하나만 켜두세요 |
| 주소 후보가 안 뜸 | 3단계 점검 → `providers.json` 의 `place_lookup` 수정 |
| 모든 사이트가 `검색 결과 없음` | 3단계 점검 → 각 사이트 `url` 수정 |
| 알림이 너무 잦음/뜸함 | 워크플로의 `SEARCH_INTERVAL_MIN`, `NOTIFY_INTERVAL_MIN` 조정 |

## 로컬 실행

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -q     # 브라우저 없이 도는 테스트
python tools/chat_sim.py                    # 대화 시뮬레이터
TELEGRAM_TOKEN=... python bot.py            # 실제 봇을 한 번 실행
```

| 파일 | 용도 |
| --- | --- |
| `tools/chat_sim.py` | 텔레그램 없이 대화 흐름 확인 |
| `tools/check_sites.py` | 예약사이트 검색이 실제로 되는지 점검 |
